# PerfectDay AI 比赛总说明

版本：2026-09-14统一定位版。名称：PerfectDay AI｜完美金鹰·假日商圈一体化随行助手。

## 唯一主线

**商圈已经打通，PerfectDay AI 让体验也真正打通。**

Concept-to-Pilot 场景验证型 MVP：完美金鹰与假日广场已经通过多个连通口实现物理贯通，项目进一步解决“人在这片一体化商圈里，接下来怎么逛、怎么衔接、变化以后怎么继续”的问题。

核心不是做两份商场攻略，也不是做一个泛城市旅游助手，而是 Journey Maintenance：维护一条正在发生、持续变化的商圈消费旅程。

AI理解 → 可信数据 → 确定性约束 → 有状态行程 → 动态重排。

当前完成核心交互和技术机制验证，未开展真实用户试用、正式商圈合作或市场效果验证。公开资料不等于实地核验。

## 为什么这个方向契合比赛

参赛主方向明确为 **商圈服务 · 用户体验**。项目直接围绕完美金鹰·假日商圈真实场景：用户面对书店、文创、咖啡、餐饮、购物、亲子与生活服务等互补业态，需要在有限时间、预算和体力下完成选择；途中遇到下雨、走累、排队或时间变化时，还需要继续做决策。

PerfectDay 的价值主张是：**把“物理连通”进一步变成“体验连通”。**

## 当前产品

首页四场景、三个快捷示例、PWA添加提示；Trip保留“本次为你考虑”、下一站/地图/完成/重排；Adjust仅改未完成部分，用餐排队先同商场实名候选，缺失才现场自选；Guide围绕一体化商圈做概况、目录与来源；最近行程为低调入口。无案例中心、会员支付或实时排队。

## 评审可验证的证据

可直接打开生产网站体验固定朋友路线，完成前两站，再用“用餐排队”把大家乐换为味千。两者均有分店级公开页面，历史保持不变。这个 Demo 证明的是：系统能把需求转成行程，并在变化后只重排未来，不代表消费者满意度或商圈收入效果。

## 试点请求

希望获得官方商户、铺位及服务设施数据、资料维护联系人和一个小范围入口。建议7天试点是以授权、数据与人员准备就绪为前提的工作安排，未开展正式合作。后续以路线生成率、地图打开率、途中重排率、重排后继续行程比例、资料更新率作为建议试点指标，先建立基线，再决定目标。

## 冻结规则

仅修复演示阻断、明显移动端问题、错误文案/地点/链接、严重可访问性与CI问题。保持当前架构和19个地点样本规模。禁止虚构用户、走访、签约、GMV或实时能力。比赛日期/提交要求以主办方当期通知为准；8月18日启幕仪式报道与用户提供的8月24日征集发布不是同一个时间节点。
