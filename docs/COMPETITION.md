# PerfectDay｜双商圈随行助手 · 参赛说明

定位：面向「商圈服务 · 用户体验」方向的可运行原型。与亲子、银发和消费体验方向有交集。参赛方向按用户提供的大赛公告整理，不假设官方评分权重。

## 一句话介绍

把“出发前推荐”延伸到“逛街途中”：理解同行人、时间、预算与喜好，利用有来源的中山双商圈地点库安排路线；途中保留已完成记录，只调整剩余安排。

## 为什么选这里

2026年8月18日，完美金鹰广场与假日广场的多个连通口启用。公开报道描述了两者在文化、购物和餐饮等业态上的互补。基于这些资料，我们提出一个产品假设：空间打通后，消费者仍可能需要帮助判断“接下来去哪”和“临时变化后还能怎么逛”。这是假设，不是已完成用户访谈得出的结论。来源与支持范围见 [DATA_SOURCES.md](DATA_SOURCES.md)。

## 已实现的闭环

1. 输入需求：百炼理解自然语言，提取同行场景、时间、预算、步行偏好、偏好地点与排除项；模型不可用时保留基础规划。
2. 生成路线：行程页先用“本次为你考虑”标签展示已结构化的需求，再从有限、带来源的地点库选择候选，按时间与预算筛选，按商场组织行程。大模型不负责编造商户或决定门店真实性。
3. 途中记录：按顺序完成或跳过一站；保留已完成时刻、预计时长和预计消费快照。
4. 剩余重排：修改剩余分钟、剩余人均预算、下一段出发时间与所在商场；组合雨天、少走路、节省预算与用餐排队情境。
5. 决策解释：说明哪些地点因时间、预算、位置或场景移除。遇到用餐排队时，优先替换为同商场、已核验的真实餐饮候选；没有合适候选时才使用现场自选兜底，不伪造实时空位或排队长度。
6. 继续使用：完整链接保留需求与进度，刷新可继续，也可复制给同行人。分享的是当时的快照，不是多人实时同步。

## 三分钟演示脚本

| 时长 | 操作 | 评审应看到的证据 |
| --- | --- | --- |
| 0:00–0:30 | 输入“和朋友逛书店、喝咖啡，再吃晚饭”，设置6小时、人均300元、正常步行 | 行程页先显示“朋友、6小时、¥300内、正常步行、书店/咖啡/正餐”等已理解条件，再生成真实地点路线 |
| 0:30–1:00 | 完成集合和书店，展开“已完成的记录” | 前两站的时间和消费记录保留；下一段时间前移 |
| 1:00–1:40 | 重排剩余行程，输入60分钟、50元、所在假日广场，勾选雨天和少走路 | 后续优先留在当前商场；移除跨区安排；已完成记录不变，并显示移除原因 |
| 1:40–2:10 | 保存、刷新、复制链接 | 进度可继续；不会重新生成整条路线或重复调用模型 |
| 2:10–2:40 | 打开商圈指南和地点来源 | 可核查的连接、书店文化、地址、商户来源与数据时效边界；指南页不承载比赛 Case |
| 2:40–3:00 | 展示一个仍有用餐安排的行程，选择“餐厅排队” | 原餐厅被替换为同商场的实名真实餐饮候选；页面仍明确未接入实时排队数据 |

比赛 Case 与用户故事放在路演材料中讲述；产品网页只保留首页三个快捷需求入口，不额外建设 Case 页面或 Demo Gallery。

## 价值主张与实际证据

| 价值主张 | 现在能提供什么 | 尚不能宣称什么 |
| --- | --- | --- |
| 途中变化后少做重复决策 | 已完成记录不变；余下路线与预算重新计算的可运行演示 | 已节省用户多少分钟、已提高满意度 |
| 更容易发现互补业态 | 真实书店、咖啡、家居、亲子与餐饮候选及来源；排队时可做同商场餐饮替换 | 已提升商户客流、转化或营收 |
| AI 使用可解释 | 行程页展示结构化需求标签；模型只负责理解语言，地点真实性与路线约束由本地数据和规则控制 | AI永不出错、模型能实时掌握商场现场状态 |
| 可从一个商圈开始维护 | 小型地点库、来源日期、边界说明，无需新增地图Key | 已获商场授权、已接入内部会员/停车系统 |
| 模型失败仍可用 | 基础规划回退、已完成记录与规则重排不依赖重复模型调用 | 实时全知导航 |

## 可扩展的落地方式（后续设想）

在获得商圈授权后，可由运营人员维护铺位、营业和设施信息，再将入口链接或二维码放到获准的服务台、酒店礼宾或活动页面。优先更新少量高价值点位。此项是部署设想，没有开展授权合作。

后续如需验证效果，可考察路线完成率、重排后继续行程比例、地图打开率和地点资料更新率。当前没有真实试用数据；不展示虚构数值、虚构增长曲线或商户证言，也不强制补做现场走访作为演示前置条件。

## 当前边界

- 手动记录进度与所在商场，不自动定位，不测量实际消费或实际耗时。
- 余额随“完成”按估算扣减，用户可以按实际情况修正。
- 只重排未完成候选；保存后移除的候选不自动重新加入，可通过浏览器返回撤销刚才的操作。
- 地点营业、收费、排队、车位和室内无障碍动线没有实时接入；“餐厅排队”是用户输入的变化条件，不是系统检测到的实时排队状态。
- 同一行程按单向换区组织；完成换区后不自动安排返回原商场。
- 分享URL包含需求文字和进度；用户不应在需求栏输入敏感资料。
- 无真实用户试用、实地走访或合作落地结果；软件回归测试不等于市场验证。
