# 80秒主 Demo 逐秒脚本

演示地址：https://perfectday-ai.vercel.app

开场前：浏览器100%缩放；从首页新建，不沿用历史行程。选“朋友聚一聚”，确认文字为“和朋友逛书店、喝咖啡，再吃晚饭。”、朋友、4小时、300元内、少走一点。备好PPT第5页作为网络异常替代。不要清空线上Key。

| 时间 | 操作与画面 | 口播 |
| --- | --- | --- |
| 00–08秒 | 首页，点朋友聚一聚 | 和朋友逛书店、喝咖啡，再吃晚饭。我们先说一句日常需求。 |
| 08–20秒 | 点击生成；等待实际结果 | AI理解需求，地点和路线约束由本地系统检查。 |
| 20–28秒 | 指向“本次为你考虑” | 它把同行场景、时间、预算和少走路要求解释出来。 |
| 28–37秒 | 展示书店、咖啡、大家乐路线 | 这次先留在假日广场：书店、咖啡，再用餐。 |
| 37–43秒 | 点高德地图；展示搜索页即返回产品 | 地图负责找地方，PerfectDay负责选下一步。现场只展示搜索，不等待定位或安装App。 |
| 43–49秒 | 完成博雅，确认已完成1站 | 书店逛完了，记录留下来。 |
| 49–55秒 | 完成DAKA，确认已完成2站及下一站大家乐 | 咖啡也喝过了，现在准备吃饭。 |
| 55–64秒 | 重排剩余行程 → 用餐排队 | 假设用户到了用餐环节，主动告诉系统：餐厅排队。这不是实时排队监测。 |
| 64–72秒 | 展示味千替换及移除原因，保存 | 系统找到同商场另一家有公开来源的餐饮候选。 |
| 72–80秒 | 下一站味千；展开已完成2站 | 前两站保持不变。它不是重新生成一份攻略，而是在原来的下午上继续决策。 |

## 演示成功判据

下一站顺序为博雅/DAKA/大家乐；调整后味千；已完成列表仍为博雅和DAKA；当前商场为假日广场。完成操作之间确认进度更新再点击。预算和时间是估算，不宣称实际省钱、省时。默认14:00为可修改规划起点，不展示“按实时营业排好晚饭”的能力。

## 网络或模型异常

模型超时会转基础规划，页面如实显示模式；可以继续同一演示并解释“理解能力降级，地点和行程状态仍可执行”。生产网站本身不可达时切PPT第5页真实截图，说明是事先截取的机制演示，不能称现场实时生成。不要现场反复刷新或随机更换复杂输入。

## 答辩备用（不在主演示重复）

1. 陪爸妈慢逛：宜得利、无咖啡、少走路；先展示需求解释，再报告走累。若初始已满足单商场约束，允许说明“无需额外调整”，不要承诺每次必然换店；可缩短剩余时间演示删减。
2. 雨天遛娃：室内亲子候选；说明雨天路线优先单商场，不将连通口视为全程遮雨。已是室内路线时无变化是正确结果。

不演：实时排队、实时停车、精确室内导航、实时活动权益、定位准确率、跨设备账号同步、离线AI、市场效果仪表盘。
