# PerfectDay AI — MVP PRD v0.5

> 当前产品版本：**MVP v0.5 · 双商圈随行助手**  
> 本文档描述当前已实现版本，不代表商场或商户官方产品方案。

## 1. 产品定位

PerfectDay AI 是一个移动端优先的商圈半日行程规划 PWA，当前聚焦 **中山 · 完美金鹰 × 假日广场** 双商圈。

核心价值不是“聊天”，而是：

> 用户告诉系统今天和谁来、玩多久、预算多少、想做什么，系统给出一条可执行路线；逛到一半发生变化时，只重排还没去的地方。

产品第一原则：**简单、好看、能直接用。**

---

## 2. MVP v0.5 目标

### 2.1 用户目标

用户可以在较短时间内完成：

1. 输入一句自然语言需求；
2. 选择出行场景；
3. 设置时长、预算和步行偏好；
4. 获得由有限地点库生成的连续路线；
5. 查看下一站、停留时间、预计消费和步行信息；
6. 通过高德地图查看地点；
7. 完成或跳过一站并保留进度；
8. 当时间、预算、天气、步行意愿或用餐情况变化时，仅重排剩余路线；
9. 刷新或分享链接后继续查看当时的行程状态。

### 2.2 当前产品验证目标

MVP v0.5 仍聚焦验证三件事：

- “场景 + 时间 + 预算 + 步行偏好 + 一句话需求”是否足够生成有用路线；
- 相比重新从头规划，“保留已完成记录，只调整后续”是否更符合真实逛街过程；
- 有来源的小型地点库是否足以支撑一个可信、可维护的商圈随行原型。

当前没有真实用户试用结果，因此不宣称已经提升客流、转化、停留时长或满意度。

### 2.3 非目标

MVP v0.5 不承担以下任务：

- 精确室内导航；
- 实时排队；
- 实时库存或票价；
- 实时停车余位；
- 支付；
- 商场会员系统；
- 商户后台；
- 自动定位与后台轨迹记录；
- 多人实时协同；
- 完整城市级地图产品。

## 3. 目标用户

### 3.1 朋友聚会

典型需求：4–6 小时、想吃饭喝咖啡或互动体验、不想一直走。

### 3.2 情侣约会

典型需求：3–6 小时、需要氛围感、书店/咖啡/体验/晚餐组合。

### 3.3 亲子家庭

典型需求：孩子有活动，大人不要太累，尽量室内。

### 3.4 陪父母

典型需求：少步行、多休息、吃饭方便、路线简单。

### 3.5 独处用户

典型需求：书店、咖啡、生活方式逛店，不需要安排过满。

### 3.6 雨天用户

典型需求：优先室内、减少换区和室外步行。

## 4. 核心用户路径

```text
打开 PerfectDay AI
        ↓
输入一句话（可选）
        ↓
选择场景 / 时长 / 预算 / 步行偏好
        ↓
生成路线
        ↓
查看“下一站”与后续安排
        ↓
完成 / 跳过一站
        ↓
保留当前进度
        ↓
途中发生变化
        ↓
修改剩余时间 / 预算 / 所在商场 / 情境
        ↓
即时预览剩余路线
        ↓
保存调整并继续行程
```

主流程优先保证手机端可以单手完成。

## 5. 当前页面

MVP v0.5 保留 4 个主要页面。

### 5.1 首页 `/`

页面目标：快速表达需求并生成路线。

当前包含：

- PerfectDay AI 品牌与双商圈定位；
- 自然语言输入；
- 6 个场景快捷选择；
- 时长、预算、步行偏好；
- 示例需求快捷填充；
- 最近一次本设备行程入口；
- 半日路线灵感；
- PWA 添加到主屏幕提示。

核心 CTA：生成行程。

### 5.2 行程页 `/trip`

页面目标：让用户优先看懂“下一站去哪”，并持续记录途中进度。

当前包含：

- 路线标题与规划模式；
- 已完成 / 待完成进度；
- 当前所在商场；
- 下一站名称、楼层/区域、停留时间、预计步行和预计消费；
- 高德地图入口；
- 完成当前站；
- 跳过当前站；
- 剩余时间与剩余预算；
- 后续时间线；
- 已完成与已跳过记录；
- 分享当前进度；
- 最近行程与撤销上一步支持。

重要原则：**结果优先于解释，下一步操作优先于长篇推荐理由。**

### 5.3 途中调整页 `/adjust`

页面目标：不推翻已经发生的行程，只重新安排剩余部分。

用户可以手动修改：

- 还能逛多久；
- 剩余人均预算；
- 下一段出发时间；
- 当前所在商场。

可组合选择：

- 下雨了；
- 想少走路；
- 再省一点；
- 餐厅排队。

页面即时展示：

- 新的后续时长；
- 预计消费；
- 预计步行；
- 后续停留点；
- 被移除地点及原因；
- 机动时间。

保存后返回行程页继续使用；已完成记录不重新生成。

### 5.4 商圈指南 `/guide`

页面目标：让产品的地点来源、商圈事实与数据边界可检查。

当前包含：

- 双商圈概况；
- 到店提醒；
- 地点搜索与商场筛选；
- 单点公开来源与查阅日期；
- 3 条可复现的途中变化演示。

演示数据用于复现功能，不代表真实用户试用记录。

## 6. 路线规划规则

MVP v0.5 不使用复杂优化模型，也不依赖多 Agent。

### 6.1 基础路线

本地规划器从有限地点库和场景模板出发，根据：

- 场景；
- 用户明确偏好 / 排除项；
- 时长；
- 预算；
- 步行偏好；
- 室内要求；

筛选并组织路线。

### 6.2 商场顺序

路线按商场聚合，减少无意义来回切换。确有两边地点时才插入跨区节点。

完成跨区后，当前单向半日路线不会自动再次安排返回原商场。

### 6.3 预算处理

系统使用地点库中的**规划预算估算**控制候选组合，不把估算写成实时价格或报价。

浏览、购物类地点若默认消费为 0，仅表示路线不强制预设购物消费，不代表商品或服务免费。

### 6.4 时长处理

路线时长由预计停留时间和预计步行时间累加。

若超过当前剩余时间，优先移除非核心、非明确偏好的未完成地点。

### 6.5 雨天与少走路

公开资料能够支持双商圈已连通，但不足以证明所有连通路径全程遮雨或无台阶。

因此：

- 雨天 / 仅室内优先集中在单一商场；
- 少走路优先减少换区；
- 不通过虚构更短步行时间来实现“少走路”。

### 6.6 途中重排

途中调整只操作 `pending` 未完成节点。

已完成记录保留当时的：

- 开始时间；
- 预计停留；
- 预计消费；
- 预计步行。

已跳过节点不会自动重新加入当前行程。

## 7. 数据策略

### 7.1 当前实现

地点数据保存在 `data/places.ts`，当前不依赖数据库和运营后台。

每个候选点保存：

- 名称、商场、楼层/区域；
- 类别和场景标签；
- 规划停留时间、预算与步行估算；
- 是否作为室内候选；
- 高德搜索关键词；
- 公开来源、查阅日期与证据边界。

详细依据见 `docs/DATA_SOURCES.md`。

### 7.2 数据原则

- 有公开依据再进入推荐池；
- 精确铺位没有可靠依据时明确写“待确认”；
- 历史开店资料不等于当前实时营业保证；
- 明确闭店的商户应退出推荐池；
- 营业、实时排队、实时票价、停车与无障碍动线未接入时不编造。

### 7.3 规模原则

当前阶段优先维护少量高价值地点，而不是追求数量。

是否扩展到更大地点库，应由真实使用反馈与数据维护能力决定。

## 8. 地图策略

### 8.1 当前不接高德 JS API

原因：

- 减少开发复杂度；
- 不需要额外地图 Key；
- 不假装具备室内导航能力；
- 让地点库与路线逻辑先得到验证。

### 8.2 当前导航方式

使用高德 URI / 关键词搜索打开地点。

PerfectDay 负责“下一站选哪里”，不负责在商场内部提供逐步导航。

### 8.3 升级条件

只有真实用户明确需要站内地图，并获得足够可靠的位置数据后，再考虑接地图 SDK 或精确 POI。

## 9. AI 策略（v0.5）

### 9.1 当前作用

百炼 Qwen 只负责把用户自然语言转换为受约束的结构化需求，例如：

- scene；
- duration；
- budget；
- walking；
- preferredPlaceIds；
- excludedPlaceIds；
- indoorOnly。

模型不能创建地点库之外的商户 ID。

### 9.2 AI 不负责

- 编造商户；
- 编造楼层；
- 编造价格；
- 编造实时营业；
- 编造排队情况；
- 独立生成最终路线事实。

最终路线由本地地点库和确定性规则生成。

### 9.3 故障降级

未配置 `DASHSCOPE_API_KEY`、模型超时或响应校验失败时，使用本地关键词解析和表单偏好继续生成路线。

因此模型增强理解能力，但不是产品能否运行的单点依赖。

## 10. 技术架构

```text
Mobile Browser / PWA
        ↓
Next.js App Router
        ↓
用户表单
        ↓
可选：Server-side Bailian intent parsing
        ↓
Local Rule-based Planner
        ↓
Source-backed Places Data
        ↓
Versioned Journey State
        ↓
Trip / Remaining Replan
        ↓
AMap External Search
```

### 技术栈

- Next.js 16
- React 19
- TypeScript
- 原生 CSS
- Vercel
- GitHub
- 阿里云百炼 Qwen（可选增强）

当前不使用：

- Supabase；
- Prisma；
- Redis；
- 地图 SDK；
- 支付 SDK；
- 重型 UI 组件库。

### 状态策略

- 行程进度：带版本的 URL 状态快照；
- 最近行程：浏览器本地存储；
- 撤销上一步：当前标签页 sessionStorage；
- 无需账号和数据库。

## 13. 成本原则

基础规划应在没有付费模型调用的情况下继续可用。

- GitHub：可使用免费方案；
- Next.js：开源；
- Vercel：当前以 Hobby 部署为主；
- 本地点库：无需数据库成本；
- 高德外部 URI：当前不使用 JS SDK；
- 百炼：可选增强，实际调用按账户权益和计费规则处理；
- 域名：当前可直接使用 `.vercel.app`。

不把必须持续充值的服务设计成基础规划的唯一依赖。
