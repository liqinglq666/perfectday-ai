# PerfectDay AI — MVP PRD v0.1

## 1. 产品定位

PerfectDay AI 是一个移动端优先的商圈半日行程规划 PWA。首个版本只服务 **中山 · 金鹰亚洲 × 假日广场** 双商圈，帮助用户在较短时间内得到一条可执行、不过度赶路、预算基本合理的消费与休闲路线。

核心价值不是“聊天”，而是：

> 用户告诉系统今天和谁来、玩多久、预算多少、想做什么，系统直接给出一条可以照着走的时间线。

产品第一原则：**简单、好看、能直接用。**

---

## 2. MVP 目标

### 2.1 用户目标

用户在 30 秒内完成：

1. 选择出行场景；
2. 设置游玩时长、预算、步行偏好；
3. 可选输入一句自然语言需求；
4. 获得 3–5 个连续地点组成的路线；
5. 查看每站时间、停留时长、预计消费；
6. 通过高德地图查看对应商圈；
7. 当计划发生变化时一键重排。

### 2.2 产品目标

第一版只验证 3 件事：

- 用户是否愿意用这种方式规划商圈半日行程；
- “场景 + 时间 + 预算 + 步行偏好”是否足够生成有用路线；
- 动态调整是否比重新从头规划更有价值。

### 2.3 非目标

MVP 不承担以下任务：

- 精确室内导航；
- 实时排队；
- 实时库存；
- 支付；
- 商场会员；
- 商户后台；
- 复杂社交；
- 完整城市级地图产品。

## 3. 目标用户

### 3.1 朋友聚会

典型需求：4 小时、300–500 元、想吃饭喝咖啡、不想一直走。

### 3.2 情侣约会

典型需求：3–6 小时、需要氛围感、咖啡/展览/晚餐组合。

### 3.3 亲子家庭

典型需求：孩子有活动，大人不要太累，尽量室内。

### 3.4 陪父母

典型需求：少步行、多休息、吃饭方便、路线简单。

### 3.5 独处用户

典型需求：书店、展览、咖啡、自由逛店，不需要安排过满。

### 3.6 雨天用户

典型需求：优先室内、减少暴露在室外的步行。

---

## 4. 核心用户路径

```text
打开 PerfectDay AI
        ↓
输入一句话（可选）
        ↓
选择场景
        ↓
设置时长 / 预算 / 步行偏好
        ↓
生成路线
        ↓
查看完整时间线
        ↓
按路线行动 / 高德查看位置
        ↓
发生变化
        ↓
动态调整
        ↓
继续原行程
```

主流程必须在手机上单手完成。

## 5. MVP 页面

MVP 只做 3 个核心页面。

### 5.1 首页 `/`

#### 页面目标

让用户快速表达需求并生成路线。

#### 页面结构

1. PerfectDay AI 品牌区域；
2. 双商圈视觉 Hero；
3. 商圈位置说明；
4. 自然语言输入框；
5. 6 个场景快捷选择；
6. 游玩时长；
7. 预算范围；
8. 步行偏好；
9. 生成按钮。

#### 场景选项

- 约会
- 亲子
- 陪爸妈
- 朋友聚会
- 独处
- 雨天室内

#### 游玩时长

- 2 小时
- 4 小时
- 6 小时

#### 预算

- 100 元以内
- 100–300 元
- 300–500 元
- 500 元以上

#### 步行偏好

- 正常走
- 少走路

#### 核心 CTA

`生成我的 PerfectDay`

---

### 5.2 行程页 `/trip`

#### 页面目标

让用户一眼看懂今天怎么走。

#### 顶部信息

- 路线标题；
- 推荐说明；
- 总时长；
- 预计消费；
- 预计步行时间。

#### 时间线

每站必须包含：

- 到达时间；
- 停留时长；
- 地点名称；
- 商圈；
- 楼层/区域说明；
- 预计消费；
- 一句推荐理由；
- 高德查看按钮。

#### 页面底部

- 调整行程；
- 重新生成。

#### 重要原则

结果必须优先于解释。页面不展示长篇 AI 对话。

---

### 5.3 动态调整页 `/adjust`

#### 页面目标

用户不需要重新输入需求，只说明“发生了什么”，系统调整剩余路线。

#### MVP 变化类型

- 下雨了；
- 少走路；
- 预算减少；
- 餐厅排队太久。

#### 调整结果

显示：

- 新总时长；
- 新预算；
- 新步行时间；
- 每站状态。

状态分为：

- 已保留；
- 已替换；
- 已缩短。

#### 核心 CTA

`应用新方案`

## 6. 路线规划规则

MVP 不使用复杂优化模型，也不依赖多 Agent。

### 6.1 场景模板

#### 约会

体验 / 文艺 → 咖啡 → 双商圈切换 → 晚餐

#### 朋友聚会

集合 → 文艺/体验 → 咖啡 → 双商圈切换 → 晚餐

#### 亲子

集合 → 亲子体验 → 休息 → 双商圈切换 → 晚餐

#### 陪爸妈

集合 → 咖啡/休息 → 双商圈切换 → 休息 → 晚餐

#### 独处

文艺 → 咖啡 → 双商圈切换 → 自由购物

#### 雨天

仅优先室内地点。

### 6.2 预算处理

系统依据预算上限优先控制可变消费项。

当前 MVP 预算是估算值，不承诺实时价格。

### 6.3 时长处理

路线按照预计停留时间 + 预计步行时间累加。

如果路线超过用户设定时长，优先删除末端非核心地点。

### 6.4 少走路

用户选择“少走路”时：

- 缩短跨区步行估计；
- 减少无必要切换；
- 保留休息节点。

## 7. 数据策略

### 7.1 MVP 数据

首版数据直接保存在仓库 `data/places.ts`。

理由：

- 只有几十个地点；
- 不需要后台；
- 不需要数据库账号；
- 不产生费用；
- 更容易调试。

### 7.2 当前数据性质

开发初期只使用双商圈公共区域和通用体验点位，避免在未核验前声称具体商户、楼层、价格和坐标绝对准确。

### 7.3 下一阶段真实商户数据

真实商户表建议逐步补齐：

- name
- mall
- floor
- category
- tags
- price range
- opening hours
- indoor
- kid friendly
- elder friendly
- recommended duration
- verified date

建议先核验 20–30 个高质量地点，而不是追求数量。

---

## 8. 地图策略

### 8.1 MVP 不接高德 JS API

原因：

- 减少开发难度；
- 不需要 Key；
- 不需要处理地图配额；
- 不需要解决室内导航。

### 8.2 MVP 导航方式

使用高德官方 URI API，通过关键词打开高德搜索结果。

这意味着：

- PerfectDay 不负责绘制地图；
- 用户可以跳转高德查看对应商圈；
- 后续真实商户数据核验后，再逐步升级为精确 POI 导航。

### 8.3 后续地图升级条件

只有当真实用户明确需要“在 PerfectDay 内看到地图”时，再接高德 JS API。

---

## 9. AI 策略

### 9.1 MVP v0.1

不依赖 AI API。

路线由确定性规则生成，因此即使没有任何 API Key，网站也能正常使用。

### 9.2 MVP v0.2

AI 只负责：

- 把自然语言转换成结构化需求；
- 提取兴趣关键词；
- 优化推荐理由文字。

AI 不负责：

- 编造商户；
- 编造楼层；
- 编造营业时间；
- 决定不存在的地点。

### 9.3 AI 故障降级

AI 不可用时，继续使用用户手动选择的场景、时长、预算和步行偏好生成路线。

## 13. 零成本原则

MVP 必须可以在不付费的情况下运行。

- GitHub：免费
- Next.js：免费
- Vercel Hobby：免费
- 本地数据：免费
- 高德 URI：无需 JS API Key
- AI：v0.1 不需要
- 域名：先使用 `.vercel.app`

任何必须充值、绑卡或产生自动超额费用的依赖，不进入 v0.1。

## 15. 开发阶段

### Stage 1 — 当前

完成 3 页 MVP、规则式 Planner、视觉系统、PWA 基础。

### Stage 2

核验 20–30 个真实商户/体验点，替换通用公共点位。

### Stage 3

接入一个免费额度 AI，仅做意图解析。

### Stage 4

根据真实用户反馈决定是否增加：

- 精确 POI；
- 地图内嵌；
- 收藏历史；
- 登录同步。

没有真实需求，不增加功能。

## 16. 产品判断标准

以后任何新功能先问：

> 一个周六下午真的来到金鹰亚洲 / 假日广场的人，会不会主动拿出手机使用它？

如果不会，只是为了“看起来技术很强”，则不进入 MVP。
