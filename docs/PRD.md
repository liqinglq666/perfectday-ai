# PerfectDay AI｜双商圈随行助手 PRD

冻结版 · 2026-09-09 · 产品行为以代码和 FINAL_QA_REPORT.md 为准。

## 1. 定位与核心问题

Concept-to-Pilot 场景验证型 MVP。把出发前推荐，变成逛街途中持续决策。

用户要协调下一站、先后顺序、同行人、时间、预算和体力；下雨、走累、餐厅排队或时间变少时，还需要在已有行程上继续。核心创新是 Journey Maintenance：维护一条正在发生、持续变化的消费旅程。

当前完成核心交互和技术机制验证，未开展实地走访、真实用户试用、正式商圈合作或市场效果验证。

## 2. 核心闭环

自然语言/表单 → 百炼 Qwen 需求解析（失败时关键词规则）→ 经公开资料核验的代表性商圈地点样本库 → 确定性规划 → 下一站/高德关键词搜索 → 完成或跳过 → 有状态行程 → 仅重排未完成部分。

AI 不创建商户、铺位、价格或实时状态。服务端校验结构、枚举和地点 ID。泛称“吃晚饭”是路线角色，不把所有餐厅候选当作必去地点；点名餐厅才作为餐饮偏好。模型调用限于提交文字需求，翻页、完成、预览与保存重排不再调用模型。

## 3. 页面及视觉优先级

| 页面 | 当前范围 | 关键约束 |
| --- | --- | --- |
| 首页 `/` | 自然语言；约会、朋友、家人、独处四个主场景；时间、预算、步行；三个快捷示例 | 示例为陪爸妈慢逛、朋友聚一聚、雨天遛娃。PWA提示保留；最近行程低调；无案例中心或灵感卡片 |

## 4. 规划与状态规则

- 时间范围90–480分钟；预算档位100/300/500/800元，均为人均规划预留。
- 时长为停留与步行估算之和；金额为规划预留，不是实时消费报价。浏览类零元不代表商品免费。
- 少走路减少换区，不虚构更短步行时间。雨天/仅室内优先单一商场；公开连通不证明全程遮雨或无台阶。
- 按商场组织顺序；需要跨区时单列连接节点。当前为单向半日路线，完成换区后不自动安排返回原商场。
- 行程保存在带版本URL快照：pending、done、skipped、clock、minutes、cash、current。完成快照保留时间和当时估算；跳过不扣时间/金额，也不假装到达。
- 最近行程在localStorage，撤销在当前标签页sessionStorage。存储不可用时完整进度链接仍可继续；分享链接包含输入文字与行程状态。
- 下雨、走累、预算和时间变化只处理pending，done保持不变；已完成/已跳过地点不自动复活。
- 用餐排队由用户主动报告；优先原餐厅同商场实名餐饮候选，遵循排除与剩余约束。没有可用候选才转现场自选。主Demo全程假日广场，因此同时保持用户当前商场。
- 条件无法满足时展示无后续安排，不虚构地点或压缩停留时间来凑路线。

## 5. 固定主 Demo

“和朋友逛书店、喝咖啡，再吃晚饭。”；朋友、4小时、300元内、少走一点。

博雅书店 → DAKA咖啡 → 大家乐。完成前两站，选择用餐排队：大家乐 → 味千拉面；当前仍为假日广场，已完成记录不动。朋友场景直接从书店开始，不以虚拟集合点占用第一站。

这是一段机制演示，不代表三处门店被实地试用。日期、营业、排队以现场为准。时间表从默认14:00起算，可在调整页校正开始时间；“晚饭”不等于已接入餐厅营业时段/订位系统。

## 6. 数据合同

19个代表性地点样本（含集合、公共区域、连通节点），并非19家商户。当前规模冻结。

`evidenceStatus`: online_listing / published_reference / public_area。
`locationPrecision`: exact / mall / area。
每条保存sourceUrl、sourceLabel、checkedAt及必要的evidenceNote。来源支持程度与当前营业保证分开；3条已闭店记录独立管理，不进入推荐池。详见 PLACE_VERIFICATION.md。

官方数据未来需映射为稳定ID、名称、商场、业态、楼层、位置精度、来源、更新时间、可用状态和规划估算；经过人工核对与现有约束测试再进入候选池。不能直接把未审核的完整目录投入生产。

## 7. 架构与边界

维持Next.js + React + TypeScript、原生CSS、本地数据、百炼解析、高德外部搜索和Vercel。无登录、数据库、会员、支付、商户后台、评论社区、实时排队/客流、复杂地图SDK或多Agent。

保留manifest、图标、standalone展示及添加到主屏幕提示。当前无完整离线应用承诺；安装体验需真机确认。

## 8. 验收与下一步

每次重要修复运行npm test、npm run typecheck、npm run build、npm run test:flow，并检查GitHub Actions、Vercel Production和线上主Demo。手机375×812、390×844、430×932；桌面1440×900。测试结论与受限项只在FINAL_QA_REPORT.md登记，不把静态检查写成真机通过。

建议7天试点须以取得官方授权、数据和配合人员为前提；Day1–2导入资料，Day3核对20–30个核心点位，Day4配置入口与场景，Day5–7小范围试用。路线生成率、地图打开率、途中重排率、重排后继续行程比例、资料更新率均为建议试点指标，尚无测量结果。
