## 已知边界与现场避免演示

- 地点是经公开资料核验的代表性样本；不保证实时营业、铺位不变、无排队或完整覆盖。HKT年度优惠页面仍含已闭店商户，故闭店证据与更新机制很重要。
- 排队由用户主动报告。替换优先原待用餐地点同商场；主Demo中该商场恰好也是当前假日广场。找不到合格候选时才现场自选。
- 时间和费用是规划估算，完成按钮扣除的是估算；可手动校正余额。默认14:00出发，“晚饭”不等于已实现餐厅营业窗口约束。
- 当前地点为商场/铺位公开描述，没有精确室内路径、无障碍全程认证或实时定位。跨区并不保证全程遮雨。
- 无实时排队、停车余位、客流、会员权益接口；不要演示或承诺这些能力。
- 网络/模型故障或应用侧限流时显示基础规划；不要把规则结果说成实时Qwen输出。PWA安装不代表离线AI可用。
- 应用侧限流不是跨所有 Serverless 实例的全局硬限额；正式公开前应在百炼账户侧设置可接受额度。
- 不临场随机输入未排练的长复杂条件；备选案例可能因原路线已满足条件而变化有限。主Demo固定输入与参数见DEMO_SCRIPT.md。
- 不演示不存在的用户、合作、满意度、转化率、GMV或节时数据；5个指标仅为建议试点指标，当前未埋点采集。

## 冻结阶段有限修复

1. 收紧模型对泛称晚饭的餐饮偏好，避免多个餐厅成为必去项。
2. 朋友模板从书店开始，快捷输入采用4小时/300元/少走路，固定主闭环。
3. 将排队提示改为“优先换同商场餐厅”，与实际机制一致。
4. Guide目录包含既有优衣库，样本库仍19个点。
5. 同步比赛文档与8页叙事，明确来源、截图及概念图性质。
6. 生成并提交 `package-lock.json`，CI 使用 `npm ci` 和 npm cache，移除一次性写权限。
7. 删除 PWA manifest 中与正式产品口径不一致的旧长按 shortcuts，安装能力不变。
8. 增加轻量 AI 调用限流与回退测试；被限流时不调用百炼，产品仍可生成基础路线。
